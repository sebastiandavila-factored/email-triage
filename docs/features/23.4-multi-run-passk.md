# Multi-run + pass^k

> Phase 4 of [exec-plan 23 — Observability + Evals SOTA](../exec-plans/23-observability-evals-sota.md).

## What it does

Runs each case **k times** and reports **pass^k** — the fraction of cases that are
correct on *all* k runs — alongside per-run accuracy. This surfaces nondeterminism
(temperature 0.2 ⇒ flaky cases) that single-run accuracy hides.

## How it works

- `dataset.evaluate(task, repeat=k)` — the framework runs each case k times, naming runs
  `"<id> [i/k]"` and grouping them via `report.case_groups()` (each
  `ReportCaseGroup.runs` holds the successful runs; failed runs go to `.failures`).
- Per case, correctness per run is recomputed from output vs the metadata category,
  yielding `dict[case_id, list[bool]]`.
- `metrics.compute_pass_hat_k(per_case_runs, repeat)`:
  - **pass^k** = cases with `sum(correct) == repeat` / total. A case with fewer correct
    runs than `repeat` (including a run that errored and is absent) does **not** pass.
  - **flaky** = cases correct on some-but-not-all runs (consistently-wrong cases are
    *not* flaky).
- CLI `--repeat K` (default 1 → unchanged behavior). `make eval-passk K=5`.
- The report prints a `PASS^k` section + a flaky list (only when `repeat > 1`).
- `eval.run` span gains `eval.repeat` (always) and `eval.pass_hat_k` (when `repeat > 1`).

**Invariant:** `pass^k ≤ accuracy` (all-runs-correct is stricter than per-run accuracy).

## Files involved

| File | Role |
|---|---|
| `evals/metrics.py` | `PassHatKResult`, `compute_pass_hat_k()`. |
| `evals/run_evals.py` | `--repeat`; `repeat=` passed to `evaluate`; per-case-runs from `case_groups()`; report section; span attrs. |
| `Makefile` | `eval-passk` (`K=` defaults to 5). |
| `tests/test_evals.py` | pure-function tests (all/mixed/none, missing run, empty, invariant) + a `repeat=3` integration test. |

## Design decisions

| Decision | Discarded alternative | Reason |
|---|---|---|
| pass^k = all k runs correct | pass@k (any of k) | we want reliability (stricter), not best-of-k |
| Missing/errored run counts against pass^k | ignore missing runs | a run that didn't produce a correct answer shouldn't count as a pass |
| `repeat` via the framework | manual re-run loop | native, also feeds `case_groups()` reporting |
| pass^k section only when `repeat>1` | always | pass^1 == accuracy (redundant) |

## Gotchas / Edge cases

- `report.case_groups()` may return `None` — coalesced with `or []`.
- Real cost is k× Groq calls; `--repeat` defaults to 1 and `max_concurrency=5` bounds it.
- With `repeat>1` the console "N cases" line counts runs (n×k); the pass^k section is the
  per-case headline.

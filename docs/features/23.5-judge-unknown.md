# Judge with "Unknown" verdict + calibration seam

> Phase 5 of [exec-plan 23 — Observability + Evals SOTA](../exec-plans/23-observability-evals-sota.md).

## What it does

Lets the LLM judge **abstain** (`verdict="unknown"`) instead of inventing scores when it
cannot fairly assess a reply, and adds a `--judge-sample N` export of judged cases for
offline human spot-check (the seam for human calibration).

## How it works

- `JudgeScore` gains `verdict: "assessable" | "unknown"`, makes the five numeric fields
  optional, and adds `reason: str`. A `model_validator` enforces: an `assessable` verdict
  must carry all five scores. An `unknown` verdict leaves them None.
- The judge prompt instructs it to abstain only when a fair score is truly impossible
  (not merely because a reply is generic/short) and to always give a one-line `reason`.
- Round-trip through the framework report (so it stays per-run-correct under `repeat`):
  - `JudgeQuality` emits a `judge_verdict` **label** (`assessable`/`unknown`); when
    assessable it also emits the numeric scores + `language_match` assertion.
  - `judge_score_from_case` reads the label: absent → judge didn't run (None);
    `unknown` → `JudgeScore(verdict="unknown")`; `assessable` → rebuilt with scores.
- `metrics.compute_report`:
  - **means are computed over assessable cases only** — abstentions don't drag scores.
  - new `judge_unknown_rate` (None when no judge ran; else fraction abstained).
- Report shows the LLM JUDGE section whenever the judge ran, with means (if any
  assessable) plus an **Unknown rate** line.
- `--judge-sample N` writes the first N judged cases to
  `evals/calibration/<timestamp>.jsonl` (email, reply, verdict, scores, reason,
  `human_verdict: null`). Gitignored — it's a run artifact.

## Files involved

| File | Role |

| `evals/evaluators.py` | `JudgeQuality` emits verdict label; `judge_score_from_case` reads it. |
| `evals/metrics.py` | `judge_unknown_rate`; means over assessable only. |
| `evals/run_evals.py` | `--judge-sample N`; `export_calibration_sample()`; Unknown-rate line. |
| `.gitignore` | `evals/calibration/`. |
| `tests/test_evals.py` | validator, unknown metrics, all-unknown, export. |

## Design decisions

| Decision | Discarded alternative | Reason |
|---|---|---|
| `verdict` + optional scores | always emit 1–5 | abstaining beats a hallucinated score |
| Validator requires scores when assessable | trust the model | guarantees downstream code never sees a half-filled assessable score |
| Carry verdict as a report **label** | module dict keyed by case | `ctx.name` ≠ per-run `rc.name` under `repeat`; the report round-trip stays per-run-correct |
| Means exclude unknowns; report a rate | count unknowns as 0 | abstentions are "no signal", not "bad" |
| Export only (human fills `human_verdict`) | auto-score human labels | calibration is a human-in-the-loop review, not an automated gate (yet) |

## Gotchas / Edge cases

- `reason` is best-effort — a weak model may leave it empty even when asked.
- If the judge over-abstains, `Unknown rate` turns yellow (≥10%) / red (≥25%).
- `--judge-sample` is a no-op without `--no-judge` omitted (needs the judge running).

## Follow-up (manual, ongoing — yours)

Periodically run `--judge-sample N`, open the JSONL, fill `human_verdict`, and compare to
the judge. This validates judge quality over time. Not a code gate.

# Online evals on live /triage

> Phase 6 of [exec-plan 23 — Observability + Evals SOTA](../exec-plans/23-observability-evals-sota.md).

## What it does

Attaches cheap, non-LLM evaluators to the production triage agent so a sampled fraction
of live `/triage` traffic is checked for empty output, language mismatch, and
out-of-range confidence — without a separate eval run and without adding latency.

## How it works

- The triage `Agent` gets a `capabilities=[OnlineEvaluation(...)]` capability
  (`pydantic-ai` 1.104 supports `Agent(capabilities=...)`; verified during discovery).
- The capability wraps `agent.run()` and dispatches evaluators **asynchronously after**
  the run completes — the response is returned first, so evals add no latency.
- **Cheap evaluators** (`email_triage/evals_online.py`, all pure & total):
  - `OutputNotEmpty` — draft reply is non-empty.
  - `ConfidenceInRange` — `0 ≤ confidence ≤ 1`.
  - `LanguageMatches` — a no-dependency Spanish/non-Spanish heuristic (accented chars +
    stopwords) agrees between the incoming email and the reply.
- Each evaluator is wrapped in an `OnlineEvaluator(sample_rate=…, max_concurrency=…)`;
  the capability uses `OnlineEvalConfig(default_sample_rate=…, enabled=True)`.
- Results surface as OTel `gen_ai.evaluation.result` events in Logfire.
- **Off by default.** `build_online_capability(settings)` returns `None` unless
  `online_eval_enabled`, in which case `/triage` runs exactly as before.

## Config

| Setting | Default | Meaning |
|---|---|---|
| `online_eval_enabled` | `False` | master switch (opt-in per env) |
| `online_eval_sample_rate` | `0.05` | fraction of runs evaluated |
| `online_eval_max_concurrency` | `2` | concurrent evaluator dispatches |

## Files involved

| File | Role |
|---|---|
| `email_triage/evals_online.py` | the 3 evaluators + `build_online_capability()`. |
| `email_triage/config.py` | `online_eval_*` settings. |
| `email_triage/services/llm.py` | `LLMService(..., capabilities=...)` → `Agent(capabilities=...)`. |
| `email_triage/deps.py` | `get_llm_service()` builds the capability from settings. |
| `tests/test_online_evals.py` | evaluator unit tests + builder enabled/disabled + `/triage` unaffected. |

## Design decisions

| Decision | Discarded alternative | Reason |
|---|---|---|
| Off by default, low sample_rate | always on | protect `/triage` latency and free-tier budget |
| Cheap heuristics only | an LLM judge online | online must be non-blocking and free |
| `max_concurrency` via `OnlineEvaluator` | global limit | the SDK exposes the cap per-evaluator |
| `AbstractCapability[None]` typing | the `AgentCapability` union alias | the alias includes a callable → pyright "partially unknown" |

## Gotchas / Edge cases

- Import split: `OnlineEvaluation` from `pydantic_evals.online_capability`;
  `OnlineEvalConfig`/`OnlineEvaluator` from the public `pydantic_evals.online`.
- `pydantic-evals` is now a **runtime** dependency (it runs in-process).
- `LanguageMatches` is a heuristic — it can misfire on very short or code-mixed text; it
  only flags obvious mismatches and never blocks the response.

# Testing: Multi-run + pass^k

> Phase 4 of [exec-plan 23](../exec-plans/23-observability-evals-sota.md).

## Prerequisites

- `.env` with `GROQ_API_KEY` for live runs.

## Automated tests

`tests/test_evals.py` (no Groq):

| Test | Asserts |
|---|---|
| `test_compute_pass_hat_k_all_mixed_none` | only all-correct counts; consistently-wrong is not flaky |
| `test_compute_pass_hat_k_missing_run_counts_against` | fewer correct than `repeat` → not passed, flaky |
| `test_compute_pass_hat_k_empty` | empty input → 0.0, no flaky |
| `test_pass_hat_k_never_exceeds_accuracy` | invariant `pass^k ≤ accuracy` |
| `test_multi_run_integration_groups_by_case` | `repeat=3` deterministic mock → pass^3 == 1.0, 3 runs/case |

Run: `uv run pytest tests/test_evals.py -k pass -v`

## Test Cases (manual — real Groq)

### TC-01: pass^k on a subset
**Action**: `uv run python -m evals.run_evals --suite regression --no-judge --repeat 3 --filter expected_category=prices`
**Expected**: 5 cases × 3 = 15 runs; a `PASS^3` section with a percentage; flaky list if
any case is correct on some-but-not-all runs.

### TC-02: full pass^k
**Action**: `make eval-passk K=5`
**Expected**: every case run 5×; `PASS^5` section; `eval.repeat`/`eval.pass_hat_k` on the
`eval.run` span in Logfire.

### TC-03: default repeat
**Action**: `make eval-quick`
**Expected**: no `PASS^k` section (repeat defaults to 1).

## Edge Cases

| Scenario | Expected |
|---|---|
| `--repeat 0` (or negative) | error "must be >= 1", exit 1 |
| a run errors out | that run absent from the group; counts against pass^k |
| all runs of a case wrong | not flaky (consistently wrong), pass^k excludes it |

## Log verification

- `eval.run` span: `eval.repeat`, and `eval.pass_hat_k` when `repeat>1`.

## Troubleshooting

| Symptom | Cause | Solution |
|---|---|---|
| pass^k seems low vs accuracy | expected — pass^k is stricter | inspect the flaky list |
| `KeyError` on a group name | case id mismatch | `group.name` must match an `EvalCase.id` |

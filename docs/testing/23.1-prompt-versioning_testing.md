# Testing: Prompt versioning (Logfire Prompt Management)

> Phase 1 of [exec-plan 23](../exec-plans/23-observability-evals-sota.md).

## Prerequisites

- `.env` with `GROQ_API_KEY` and (optionally) `LOGFIRE_TOKEN`.
- `uv sync` done.
- MANUAL (yours): in the Logfire UI, prompt `prompt__email_triage_system` created and
  the `production` label promoted. The code works with the fallback even before this.

## Automated tests

`tests/test_prompt_versioning.py` (no Groq, no network):

| Test | Asserts |
|---|---|
| `test_get_system_prompt_falls_back_to_code_default` | unresolved Logfire → `SYSTEM_PROMPT`, contains all 5 categories |
| `test_system_prompt_resolved_once_per_process` | `@lru_cache` → `.get()` called once for N reads |
| `test_get_system_prompt_uses_configured_label` | resolves with `label="production"` |
| `test_category_drift_guard_warns_and_does_not_raise` | missing categories → `prompt.category_drift` warning, no exception |
| `test_category_drift_guard_silent_when_complete` | full prompt → no warning |
| `test_llm_service_builds_agent_with_system_prompt` | passed prompt reaches the agent |

Run: `uv run pytest tests/test_prompt_versioning.py -v`

## Test Cases (manual)

### TC-01: Works with code fallback (no managed prompt)
**Action**: with no `prompt__email_triage_system` published in Logfire, start the app
(`make dev`) and `POST /triage` with a valid email.
**Expected**: normal classification + draft reply; startup log `startup` shows
`prompt_chars` > 0.

### TC-02: Managed prompt is consumed
**Action**: publish a version in Logfire and promote `production`; restart the app.
**Expected**: the resolved prompt comes from Logfire; behavior reflects the new prompt.
Resolution happens once at startup (no per-request fetch).

### TC-03: Category-drift guard
**Action**: publish a prompt version that omits a category word (e.g. drop "refunds"),
promote it, restart.
**Expected**: startup logs a `prompt.category_drift` warning listing the missing
category; the service still starts and serves traffic.

## Edge Cases

| Scenario | Expected |
|---|---|
| `LOGFIRE_TOKEN` absent | `.get()` returns the code default; no crash |
| Logfire unreachable | same — `reason="code_default"` |
| `PROMPT_LABEL` env override | resolves that label instead of `production` |


## Troubleshooting

| Symptom | Cause | Solution |
|---|---|---|
| `ValueError: variable ... already registered` | `logfire.var(name=...)` called more than once | keep it at module scope only |
| Prompt changes not picked up | resolved once at startup | restart the app after promoting a label |
| Tests pollute each other | stale `@lru_cache` | `get_system_prompt.cache_clear()` in the test |
